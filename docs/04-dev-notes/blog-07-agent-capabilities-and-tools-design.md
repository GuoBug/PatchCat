## 引言：当提示词流水线遇上“自主思考”

在 PatchCat 的前几个版本中，我们打造了一套基于 Kahn 算法的高性能有向无环图（DAG）拓扑调度引擎：用户在画布上把 Input、Prompt、LLM、Code、Condition 分支连成线，点击运行后，引擎按照波次层级推进执行。

这套模式在固定 SOP（如意图识别工单分派、多模型评测盲测）中表现非常稳定。但在实际业务中，我们很快遇到了一个天花板：
> **如果任务的解题步骤不是预先固定的呢？**  
> 比如：“请帮我按最新汇率折算 450 美元为人民币，并扣除 3% 的跨境手续费，计算出最终到手金额。”

在纯流水线模式下，大模型要么硬着头皮“心算”给出错误数字，要么需要开发者在画布上手工配置极度复杂的嵌套路由。

大模型需要具备**“自主判断该用什么工具、拿到工具结果后再继续推导”**的能力。  
在刚刚发布的 `v0.4.2` 中，我们正式推出了 **原生 Agent 节点与 Tools 工具调用体系**，让 PatchCat 从“静态流水线”跃升为“自主智能体”。

本文全程坦诚记录我和 AI 搭档（AI Pair Programming）在攻坚 Agent 与 Tools 过程中的**关键节点双向启发、方案权衡、底层机制与实战用法**。水平有限，代码与架构难免有青涩之处，诚挚欢迎社区同行与资深架构师批评指正！

## 一、关键节点双向启发：人机协同的架构取舍

回顾这一里程碑的演进，系统走向并不是简单地“遇到报错才修 Bug”，而是一系列决定架构生死走向的**关键节点（Critical Milestones）双向启发**。

### 1. 人提的关键点：拒绝“意面画布”，追求极简心智模型
- **直觉与痛点**：传统工作流工具为了实现 Loop 和 Agent，往往允许用户在画布上直接画“回流连线（Back-edges）”。但在实际测试中，我发现一旦画了环路，连线交叉错乱，画布迅速沦为无法维护的“意面式图谱（Spaghetti Graph）”，用户根本搞不清当前跑到第几圈。
- **产品诉求**：**必须把 ReAct 的自主循环收敛在单个独立的 Agent 节点内部**！
  - 全局画布依然是清爽纯粹的 DAG，保持 Kahn 算法分层拓扑调度的高性能；
  - 循环迭代细节通过节点徽章与执行事件流式向用户呈现；
  - 同时，Tools 不能只能写固定脚本，必须能把画布上已经配置好的其他节点（如已配好的知识库 RAG 检索节点）当成现成工具调用！

### 2. AI 提的关键点：流式碎片拼装与死循环熔断守卫
- **工程规约与隐患**：AI 敏锐指出了两个底层协议的隐蔽陷阱：
  - **SSE 分片截断风险**：在流式输出（Server-Sent Events）中，主流模型（OpenAI、Gemini、DeepSeek）的 `tool_calls` 是作为零散的 `delta.tool_calls` 碎片化推送过来的（甚至函数的 JSON 入参字符串会被截断成多个字符分块）。如果不在客户端设计多键累加器，拼接出来的 JSON 必然频繁抛出 `Unexpected end of JSON` 崩溃；
  - **模型幻觉死循环**：大模型在遇到矛盾指令或工具报错时，极易产生“反复调用同一无效工具”的病态死循环，单靠前端等待会迅速烧光用户的 API Token 甚至卡死浏览器。必须在引擎内核设立带强制熔断的 `maxIterations` 步数看门狗，并全程透传 `AbortSignal`。

## 二、方案权衡与底层 ReAct 引擎剖析

针对上述核心分歧，我们在动手前对比了三种业界常见的 Agent 落地形态：

| 架构形态 | 优势 | 劣势与工程代价 | 最终选型 |
| :--- | :--- | :--- | :---: |
| **形态 A：画布级全局回边** | 图逻辑在顶层完全暴露 | 破坏 DAG 调度模型，死循环排查困难，节点状态脏重绘严重 | ❌ 放弃 |
| **形态 B：节点内聚 ReAct 闭环** | 保持拓扑调度极致纯粹，边界清晰，具备极高单测与容错性 | 需通过事件流展开循环内部 trace | ✅ **采纳** |
| **形态 C：嵌套独立子画布** | 扩展性极强 | React Flow 多实例开销巨大，状态切片同步成本高 | ❌ 规划后续探索 |

### 核心 ReAct 执行流机制

最终我们选定并实现了**节点级内聚 ReAct 闭环**。整个执行时序如下：

```
1. 提取上游输入并组装 System Prompt 与 User Query；
2. 将当前节点绑定的 tools 配置转为标准 OpenAI Function Calling 协议；
3. 进入自主迭代循环（限制最大 maxIterations 轮）：
   a. 向大模型发起流式推理（开启 tools 支持）；
   b. SSE 累加器收集 token 与 delta.tool_calls；
   c. 判定：
      - 若模型返回 tool_calls：
        ① 发射 AGENT_TOOL_CALL 运行时事件；
        ② 根据工具类型分发至路由执行器（沙箱脚本 / HTTP / 画布节点）；
        ③ 将执行结果包装为 { role: 'tool', content: ... } 回注上下文；
        ④ 标记步数计数器 +1，继续下一轮思考；
      - 若模型返回纯文本内容（无 tool_calls）：
        ① 判定任务达成，提取最终回答；
        ② 终止循环。
4. 汇总多轮 Token 消耗与执行耗时，向下游输出。
```

## 三、Tools（工具）到底怎么用？

在 `v0.4.2` 中，我们在 Agent 节点的属性面板中提供了开箱即用的可视化工具配置。目前支持 **3 种核心工具形态**：

### 1. `builtin_code`（沙箱代码工具）—— 专治大模型的“算术硬伤”
* **适用场景**：高精度算术、复杂日期计算、正则文本清洗、数组排序过滤。
* **执行原理**：在客户端独立的 Web Worker 沙箱中运行，剥离了敏感 DOM 与网络权限，输入参数通过 `inputs` 注入，使用 `return` 返回结果。
* **实操配置示例（代数计算器）**：
  - **Tool Name**: `calculate`
  - **Description**: `用于精确计算数学算式，例如加减乘除、汇率与费率折算`
  - **Code Implementation**:
    ```javascript
    return { result: eval(inputs.expression) };
    ```
  - **JSON Schema**:
    ```json
    {
      "type": "object",
      "properties": {
        "expression": {
          "type": "string",
          "description": "要计算的数学算式，例如 450 * 7.25 * 0.97"
        }
      },
      "required": ["expression"]
    }
    ```

---

### 2. `builtin_http`（外部 REST API 工具）—— 让大模型连接真实世界
* **适用场景**：查实时天气、查快递物流、调用内部微服务或企业私有系统。
* **执行原理**：引擎接收大模型生成的结构化参数，动态向指定 URL 发起 POST 请求，并将 HTTP Response 自动回传给大模型。
* **实操配置示例（汇率牌价查询）**：
  - **Tool Name**: `get_exchange_rate`
  - **Description**: `查询两个货币之间的实时外汇牌价`
  - **API URL**: `https://api.exchangerate.host/convert`
  - **JSON Schema**:
    ```json
    {
      "type": "object",
      "properties": {
        "from": { "type": "string", "description": "源货币代码，如 USD" },
        "to": { "type": "string", "description": "目标货币代码，如 CNY" }
      },
      "required": ["from", "to"]
    }
    ```

---

### 3. `canvas_node`（画布既有节点复用）—— PatchCat 的组合杀手锏
* **适用场景**：直接调用当前画布中已经配置好的「知识库检索节点」或「Prompt 处理节点」。
* **执行原理**：开发者在 Implementation 中填入目标节点的 ID（例如 `knowledge_faq`）。当 Agent 判定需要调用知识库时，引擎会挂起当前 Agent，递归调用 `knowledge_faq` 节点获取检索切片，再将知识库输出无缝注回 Agent！

## 四、极速上手：体验官方内置的双语 Agent 预设

不用从零配线，我们在 `v0.4.2` 中内置了官方预设 **「自主智能体工具调用与运算流」**（英文：`Autonomous Agent with Tool Calling`）：

1. 打开 PatchCat，在左侧工作流抽屉的 `预设模版` 目录中点击该预设；
2. 画布自动载入 3 个节点：`用户提问输入` ➔ `智能财务助手 Agent` ➔ `最终回答`；
3. 点击 Agent 节点可看到已绑定了 `get_exchange_rate` 与 `calculate` 两个工具；
4. 点击顶部 **Run Workflow** 执行默认测试问句：
   > *“我有 450 美元，请帮我按最新汇率折算为人民币，并扣除 3% 的跨境手续费，计算出最终到手人民币金额。”*
5. **执行效果**：
   - Agent 节点亮起紫色脉冲光效；
   - 第一轮：模型思考后调用 `get_exchange_rate` 工具，拿到牌价 `7.25`；
   - 第二轮：模型将 `450 * 7.25 * (1 - 0.03)` 送入 `calculate` 工具，精确算出 `3164.025`；
   - 第三轮：模型综合各步依据，生成条理分明的回答推送到输出节点。

## 五、独立查证与极限测试实录

按照我们的研发铁律，任何新能力在合入主干前必须经过严格的**独立查证与极限边界测试**。我们在 `tests/agent-node.node.test.ts` 中针对性构造了多项边界用例：

1. **死循环与上限熔断断言**：故意构造“输入要求求解不可能的任务”，模拟模型不断重复调用工具的死循环场景，实测验证引擎在达到 `maxIterations: 5` 时是否能安全截断退出，避免无休止消耗 Token；
2. **SSE JSON 分片健全性验证**：模拟低带宽下大模型将参数切碎为每片 1~2 字符的极端场景，验证累加器无任何丢失与解析崩溃；
3. **Loop 迭代节点的边界容错**：给 Loop 节点输入空数组、非 JSON 字符串甚至是数字时，验证系统能否平滑降级而非页面白屏。

> **当前版本测试指标**：全量 **195 项自动化测试用例 100% 绿灯通过**，TypeScript 严格模式 0 警告，Vite 生产打包通过。

## 六、进阶使用经验总结 (Pro Tips)

在实战调试 Tools 时，有几个非常关键的实践技巧分享给各位开发者：

1. **Tool 的 Description 是大模型调用的唯一指南针**：
   大模型“看不到”你的代码实现，它纯粹依靠你写的 `Description` 和 Schema 中的字段解释来做出调用决策。
   - ❌ 简陋描述：`"calc"`
   - ✅ 详尽描述：`"高精度执行数学代数运算，支持加减乘除与百分比折算，接收标准数学算式字符串"`。描述越严谨，模型调用的准确率提升越显著。
2. **在 System Prompt 中加入“工具优先法则”**：
   大模型往往有“自负幻觉”，面对算术容易自行盲猜。在 Agent 的系统提示词中加上：
   > *“当面对数学运算、汇率转换或客观事实查询时，严禁凭记忆猜测，必须优先调用提供的对应工具进行实证。”*
   能立竿见影地压制模型的盲猜心理。
3. **合理配置 `maxIterations`**：
   一般简单任务设为 `3 ~ 5` 轮即可，复杂分析可设为 `8 ~ 10` 轮，既给足思考重试空间，又保留坚固的安全底线。
