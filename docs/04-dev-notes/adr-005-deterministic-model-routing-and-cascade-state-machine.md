# ADR-005: 确定性模型级联路由与自愈升级状态机架构

## 核心金句先行 (Quotable Snippet)

> **“在 AI 工作流编排的成本质量天平上，优秀架构追求在确定性约束下把任务做对做省。模型路由的本质是基于失败模式的数据分层与级联升级：用经济模型裸跑接住确定性简单请求，用局部自愈消化轻度格式瑕疵，仅在廉价预算耗尽或触发语义门禁时升级强模型，让系统在质量零妥协的前提下获得结构性成本优势。”**

---

## 一、 决策背景与核心痛点

在 PatchCat（端侧与浏览器原生 AI 工作流编排器）演进到 Module 3 之前，节点执行仅支持静态绑定单模型。这在真实工业化落地中面临两难困境：

1. 顶配模型全量通跑成本高昂：若所有工单全量调用大参数模型（如 DeepSeek-V3 / 72B），推理成本高达 $0.40/1M tokens，响应延迟居高不下；
2. 轻量模型单打独斗频繁翻车：若全量采用免费或低成本轻量模型（如 Qwen2.5-7B，$0.05/1M tokens），面对复杂陷阱或长链推理时极易产生语法溃败或语义偏航；
3. 盲目级联引发 F6 漏洞漏斗：若简单采用“契约校验通过即返回”的粗糙级联，由于契约断言只能防御格式类错误，无法检测语义掩盖（F6），会导致 20% 契约合规但分类错误的异常工单（如 Case #27、#30）被静默放行给终端用户。

为此，PatchCat 必须建立一套兼具成本效益、语义敏感度与确定性边界的模型级联路由机制。

---

## 二、 架构选型与三种形态权衡

| 路由形态 | 运行原理 | 核心优势 | 致命缺陷 | 决策结论 |
| :--- | :--- | :--- | :--- | :---: |
| 1. 静态语义分类路由 (Semantic Router) | 请求入口前置 Embedding 向量模型，对用户 Prompt 进行分类分流。 | 响应极快，无需两次调用模型。 | 对深层隐性意图极易误判，表面简单的文本若暗藏陷阱将被彻底误导。 | 拒绝作为核心防线 |
| 2. 试探级联升级 (Cheap-First & Escalate) | 优先调用 Tier 1 经济模型，契约或语义失败后带着前序错误诊断上下文无缝升级至 Tier 2 强模型。 | 结合确定性断言与局部自愈，兼顾极致成本压缩与可靠性兜底。 | 遇到复杂任务时存在一次低成本模型的试探开销。 | **采纳为核心架构** |
| 3. LLM-as-a-Router (大模型裁决路由) | 部署独立微型 Agent 分析 Prompt 并决策分发目标。 | 动态编排能力强。 | 增加额外往返延迟与 Token 账单，裁决器自身存在不可忽视的幻觉风险。 | 暂不引入 |

## 三、 核心架构设计与四大关键决议

```
  ┌────────────────────────────────────────────────────────────────────────┐
  │                   Cheap-First & Escalate Cascade Hub                   │
  │                                                                        │
  │  [User Prompt] ─────────────────────────────────────────────────────── │
  │        │                                                               │
  │        ▼                                                               │
  │  [Tier 1: Qwen2.5-7B ($0.05/1M)] ── Initial Speculative Run            │
  │        │                                                               │
  │        ├──► [L1/L2 Contract Passed?] ──► [Track 2 Semantic Gate]       │
  │        │          │                               │                    │
  │        │          │ (No)                          ├──► (Pass) ──► ✅ T1│
  │        │          ▼                               │     (43% Zero-Esc) │
  │        │    [Cheap Retries <= 2?]                 └──► (F7 Trip)       │
  │        │          │                                        │           │
  │        │          ├──► (Yes) ──► [In-Place Self-Heal] ──► ✅ T2       │
  │        │          │                 (Diagnostic Triad)    (37% Preserved│
  │        │          ▼                                        │           │
  │        │       (Exhausted)                                 │           │
  │        ▼          ▼                                        ▼           │
  │  [Model Escalation Watchdog] ◄─────────────────────────────┘           │
  │        │                                                               │
  │        ▼  Context Carry-Over: Passes failure trace & diagnostic triad  │
  │  [Tier 2: DeepSeek-V3 / Strong Model ($0.40/1M)] ────────────────────►  │
  │        │                                                               │
  │        └──► Output Validated & Resolved ──► ✅ T3 Handled (20%)        │
  └────────────────────────────────────────────────────────────────────────┘
```

### 决议 1：升级阈值严设于“便宜模型自愈预算耗尽后”
在 30-case 基准中，**T2 占 37%**。这部分用例便宜模型首轮偶有瑕疵，但通过提示层局部自愈均能成功救回。
若将升级判据设在首轮失败处，系统将白白为这 37% 的工单支付 8 倍溢价。因此，升级阈值严格定在 `cheapAttempts > maxCheapRetries`。

### 决议 2：命名体系严格解耦
提示词层自愈升级为 `SelfHealingEscalationLevel`（`surgical_prescription` / `golden_exemplar`）。
模型级路由升级严格定义为 `ModelTier`（`tier1_cheap` / `tier2_strong`），彻底消除系统演进中的概念混淆。

### 决议 3：上下文继承与定向自愈 (Context Carry-Over)
当触发模型升级时，绝不丢弃经济模型的失败现场。系统将经济模型的 `rawOutput` 以及诊断三元组（违规值、约束规则、修复处方）注入提示词历史，强模型以黄金示例与定向消歧为起点执行修复。

### 决议 4：双轨升级防线与 F7 动作优先权门禁 (Track 2 Semantic Gate)
单纯契约断言存在 F6 语义盲区。针对工单同时包含浓重缺陷描述（“假货/暗损”）与核心退款诉求（“立即退款”）的极端情形（如 Case #27、#30），系统增设静态语义冲突检测。一旦检测到分类误落于 `quality`，立即触发动作优先权消歧并升级，阻断错误外溢。

## 四、 代价、妥协与已知边界 (Trade-offs & Boundaries)

真实的工程方案绝无万灵药，必须坦承本 ADR 的代价与边界：

1. 长尾任务轻微延迟惩罚：对于确实需要强模型介入的 T3 任务，需先经历经济模型的试探或自愈，比直接调用强模型多产生约 1.5~2.5 秒的首包延迟；
2. F3 标注争议不可靠升级边界：30-case 中 Case #8、#21、#28 属于 Ground Truth 标签本身存在争议的用例。此类用例无论升级至何种大模型，均可能因理解深入而与有瑕疵的基准答案冲突，不可盲目归因于算力不足；
3. 零预算与单模型约束友好：在未接入付费模型或仅有免费配额的环境下，路由系统可完整在单模型内切换提示词策略或执行 Mock 降级，保障系统健壮性。

## 五、 实施效果与回归度量

全库自动化回归测试覆盖全部 7 项核心断言（`tests/model-routing.node.test.ts`）：
* T1 路径验证：经济模型首轮命中，升级次数为 0，录得 87.5% 成本节约；
* T2 路径验证：经济模型首轮格式不合规，第 2 轮自愈成功闭合，升级次数保持为 0；
* T3 路径验证：廉价自愈耗尽后无缝升级强模型，上下文完备承接；
* Track 2 门禁验证：Case #27 在契约合法但分类受前置描述词误导时成功触发语义拦截；
* 零崩溃保障：双层均失效时输出优雅降级结果，全库 379 个单测 100% 通过。
