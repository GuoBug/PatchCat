## 🧭 一、核心工程认知沉淀 (Core Axioms & Principles)

在推进 v0.4.12 的自愈状态机与真实模型基准测试过程中，我们与资深评审同行反复碰撞，沉淀出了五条决定 PatchCat 架构底线的设计原则：

1. **分层防御哲学**：
   > *“L1 守物理语法，L2 守业务契约，L3 守系统鲁棒，L4 守调度可用。确定性编排不是剥夺 LLM 的创造力，而是给概率性的输出套上确定性的工程安全气囊。”*
2. **校验与真实的哲学界限**：
   > *“Zod 只能证明‘没查出违规’，不能证明‘数据正确’。已满足 $\neq$ 正确。未被点名不等于正确：朴素字段冻结只会把幻觉锁死在局部优化陷阱中。”*
3. **引擎架构纯粹性铁律**：
   > *“把这段引擎代码拿去做法律合同审查工作流，需要改吗？需要 $\to$ 就是业务下沉了。引擎必须对业务领域彻底盲视，业务规则永远归仓 Presets。”*
4. **重试与自愈的本质区别**：
   > *“缺少结构化反馈的重试，只是让模型在同一个局部极小值反复打转（同构重试陷阱）；真正的自愈不是‘盲目重跑一次’，而是‘带病历复诊’。”*
5. **科学归因底线**：
   > *“端到端通过率的跃升，不是来自模型首轮犯错变少，而是来自自愈状态机在工程调度层强悍的兜底与挽回转化能力。”*

## 🛠️ 二、架构演进复盘：从“粗放重试”到“四层防御体系”

### 1. 痛点根因：传统 AI 工作流的“脆性断流”
当下游 Condition 分支路由或 Code 脚本需要消费强类型数据时，大语言模型的概率性输出普遍导致：
- **语法破碎**：未闭合的括号、Markdown 代码块围栏导致 `JSON.parse` 抛错崩溃。
- **业务穿透**：JSON 语法合法，但字段取值非法（如枚举捏造、数值越界）或多个字段逻辑打架（跨字段契约违规）。
- **同构死锁**：若仅简单告诉模型“格式不对请重试”，缺乏结构化病历反馈，模型往往在同一局部极小值反复生成相同错误。

### 2. 四层确定性防线实现
- **L1（约束解码与语法清洗）**：实现 `json_schema` $\to$ `json_object` $\to$ `none` 三级显式协商与降级；通过 `repairJsonL1` 在客户端毫秒级剥离 Markdown 围栏并修补未闭合大括号，确保物理语法解析成功率 100%。
- **L2（运行时领域语义防御）**：以 Zod 作为 Single Source of Truth，上游导出标准 JSON Schema，下游执行零 Throw 的 `.safeParse()`，防御数值范围、枚举约束与 `.refine()` 跨字段业务契约。
- **L3（错误记忆自愈状态机）**：
  - Round 1 实施**三要素手术刀处方 (Triad Surgical Feedback)**：违规当前值 + 违反规则 + 具体纠偏建议；
  - Round 2+ 识别同构微调，顶格升级为**全量 Schema 注入 + 黄金示例 (Golden Exemplar)** 锚定；
  - 针对截断 (`finish_reason === 'length'`) 注入紧凑压缩处方；针对 DeepSeek 空包原地无污染干净重发。
- **L4（零抛错优雅降级契约）**：2 次重试预算耗尽后，严禁 `throw Error`，产出标准化 `{ _validationFailed: true, errors, raw }` 降级对象，交由下游 Condition 节点安全捕获并路由至备用兜底分支。

## 🔍 三、关键节点实证：局部优化陷阱与“字段冻结”回滚

在探索自愈状态机抗震荡策略时，我们曾尝试在 Round 1 报错时要求模型“仅修改被点名报错的字段，其余字段字面严格保持不变（字段冻结）”。

### 实测极端反例证伪（用例 #7 尸检）
- **输入背景**：客户咨询商品未收到申请退款，真实 Ground Truth 为 `category = 'refund'`。
- **模型 Round 1 输出**：`{ category: "logistics", urgency: 5, summary: "签收后未收到货物，怀疑丢件" }`。
- **Zod 拦截点**：由于物流类工单不应占高紧急度，Zod 仅报错了 `[urgency, summary]` 跨字段冲突，并未报错 `category`（因为 `"logistics"` 本身符合枚举规范）。
- **冻结策略死锁**：朴素冻结将未被点名的 `category = "logistics"` 强行锁死，剥夺了模型在 Round 2 自主将分类纠偏为 `refund` 的空间，导致后续轮次无论如何修正 summary，都陷入不可调和的逻辑死循环。
- **架构定论**：**已满足 $\neq$ 正确**。Zod 只能证明“未被点名”，无法证明“已经正确”。必须坚决剔除朴素字段冻结，保持开放纠偏空间，依靠黄金示例引导结构对齐。

## 🏛️ 四、架构纯粹性红线治理 (Presets 归仓)

在外部架构评审中，同行提出了决定性的边界测试：
> *“把这段引擎代码拿去做法律合同审查工作流，需要改吗？”*

我们据此对代码库进行了彻底的去领域化清洗：
1. **剥离业务 Schema**：将 `TicketSemanticSchema` 从 `src/engine/structured-output.ts` 迁入 `src/presets/self-healing-scenarios.ts`。
2. **通动态注册表解耦**：移除 `obj['name'] === 'TicketSemanticSchema'` 静态代码，升级为引擎通用的 `schemaRegistry` 机制。
3. **测试场景归仓**：将 130 行业务 Mock 数据和工单场景完全迁移至 Presets 资产层，引擎类型收敛为通用 `testScenario?: string`。

现在的引擎代码拿给任何法律合同、金融风控或医疗问诊工作流使用，核心引擎代码 0 修改。

## 📊 五、真实模型评测与统计口径严谨性

在基于硅基流动 `Qwen/Qwen2.5-7B-Instruct` 免费档模型（14 个独立 Case $\times$ 3 轮重复 = 42 样本对）的实测中，严格执行双口径统计检验：

- **按样本配对 (By-Sample, $n=42$)**：McNemar 精确检验 **$p = 0.00195 < 0.01$**（**极显著**）；
- **按独立用例 (By-Case, $N=14$)**：McNemar 精确检验 **$p = 0.125 > 0.05$**（**不显著**）；
- **归因实情**：L1 消除全部语法崩溃（3 $\to$ 0），模型首轮跨字段违规反而增多（8 $\to$ 13），端到端合规率从 69.0% 提升至 92.9% 的 +23.9pt 增益，几乎 100% 来自 L2/L3 自愈状态机的高效挽回，绝非模型首轮犯错变少。
