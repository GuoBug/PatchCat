## 〇、摘要卡：四个指标必须同时报告

单一指标会掩盖维度退化。本报告的全部结论建立在以下四类指标之上：

| 类别 | 指标 | A 组 | B 组 | 变化 |
|---|---|---|---|---|
| **合规** | 端到端契约合规率 | 69.0% (29/42) | 92.9% (39/42) | **+23.9pt** |
| **正确性** | 意图分类（category）准确率 | 85.7% (36/42) | 78.6% (33/42) | **−7.1pt** ⚠️ |

| **成本** | 每修好一样本的边际成本 | — | 2658 tok | — |

> **本文最重要的一句话**：合规率 +23.9pt 的同时，语义准确率 −7.1pt。**这两个数字必须同时出现**，只报前者是不完整的结论。

## 一、方法：实验设计与数据来源

### 1.1 实验配置

| 项 | 值 |
|---|---|
| 模型 | Qwen/Qwen2.5-7B-Instruct（SiliconFlow） |
| 温度 | 0.2 |
| 数据集 | 14 个用例（10 easy + 4 adversarial）|
| 重复次数 | 3 → 每组 42 个样本 |
| A 组 | 仅 prompt 约束（无 schema、无自愈） |
| B 组 | L1 受限解码 + L2 Zod 契约校验 + L3 自愈状态机 |
| 变量隔离 | `UNIFIED_SYSTEM_PROMPT` 两组完全相同（`run-siliconflow-ab-test.ts:129`） |

### 1.2 两条正确的方法论设计（值得保留）

1. **Ground truth 不喂给校验器**：`expectedCategory` / `expectedOrderId` 仅用于正确性度量，绝不参与契约校验——避免"用答案证明答案"的自证循环。
2. **系统提示词两组统一**：保证 A/B 的唯一变量是"结构化输出与自愈机制"本身。

### 1.3 统计口径

- 配对 **McNemar 精确检验**，双口径；Wilson 95% 置信区间
- **按样本**（n=42）：p = 0.00195 ✅ 显著
- **按独立用例**：b=4（A 败 B 胜：#3、#7、#12、#13）、c=0 → **p = 0.125** ⚠️
- **关键澄清**：b=4、c=0 时 p 的**数学最小值就是 0.125**（2 × 0.5⁴）。这不是"效果不确定"，而是 **n=4 的样本量上限**。要达到 p < 0.05，至少需要 **6 个 discordant 且全为 b**（6:0 → p = 0.0313）。
- → 行动项是**扩用例数**，不是加 repetition。repetition 度量"模型不确定性"，用例数度量"场景覆盖"，两者不可互换。

## 二、成功切片：先理解自愈为何有效，才能界定它的边界

**分析失败前先看成功**——因为只有知道自愈"为什么能修好"，才能判断它"什么时候修不好"。

### 2.1 主证：Case #13（激烈情绪的物流投诉）

- **输入**：`订单号 ORD-333333 的包裹卡在中转站整整三天没有任何动静了，客服电话打了五遍都没人接，我非常愤怒，必须马上给我一个说法！`
- **GT**：`category = logistics`
- **A 组**：3/3 输出 `urgency = 5` → 触发跨字段契约「logistics ⇒ urgency ≤ 3」→ **0/3 全灭**
- **B 组 trace**：

```
R1  urgency=5, category=logistics, summary="包裹中转站滞留多日，客服电话无法接通。"
    → L2 拦截：「物流类工单不涉及资金流转，urgency 必须 ≤ 3」
    → 处方同时给出：category 与 urgency 任意一个都可改，请判断哪个判断错了
R2  urgency=3, 其余字段不变 → 通过   ✅ 3/3 全数自愈
```

### 2.2 机制：收敛型修复 vs 生成型修复

| 修复类型 | 需要的动作 | 自愈能否完成 | 例 |
|---|---|---|---|
| **收敛型** | 从已有信息中**删除 / 收敛 / 调整** | ✅ 能 | #13 数值 5→3；#1/#3 字数补足 |
| **生成型** | 必须**产生新的、有信息量的内容** | ❌ 不能 | #11（见 F2） |

> **自愈的有效性边界**：它能修"改一下就行"的违规，修不了"得新写点东西"的违规。这条边界决定了后面所有失败模式的走向。

### 2.3 B 组成功构成

| 构成 | 数量 | 占比 |
|---|---|---|
| 首轮直接通过（S1） | 31 | 73.8% |
| 被 L2 拦截 | 11 | 26.2% |
| — 其中自愈救回（S2） | 8 | 19.0% |
| — 其中降级托底（S3） | 3 | 7.1% |

## 三、精确归因（可复算口径）

```
Baseline (A)          69.0%  (29/42)
   │
   ├─ L1 受限解码 + Schema 注入（首轮通过 29→31）   +4.8pt
   ▼
B 组首轮 (S1)          73.8%  (31/42)
   │
   ├─ L3 自愈状态机救回 8 个样本                    +19.0pt
   ▼
B 组最终               92.9%  (39/42)
```

**自愈贡献 19.0pt，L1/提示词贡献 4.8pt。**端到端提升主要来自自愈，而非"模型首轮犯错变少"——这一点与直觉相反，值得在结论中明确。

**成本对应**：A 333 tok → B 966 tok（**×2.90**），延迟 2465ms → 2857ms（+16%）。**每修好一个样本的边际成本为 2658 tokens。**

## 四、双轴正交分析框架

> **严禁把"终止状态"与"失败根因"并列。**二者不在同一根轴上：每一个根因失败最终都以某个终止状态收场，并列会导致重复计数与分类交叉。

### 4.1 终止状态轴（Termination States）

| 编号 | 状态 | 定义 | B 组分布 |
|---|---|---|---|
| **S1** | 首轮直通 | 首轮即通过 L1 + L2 | 31/42（73.8%） |
| **S2** | 自愈收敛 | 首轮被 L2 拦截，L3 反馈后修正通过 | 8/42（19.0%） |
| **S3** | 降级托底 | 3 次调用预算耗尽，L4 Never-Throw 返回 `_validationFailed` | 3/42（7.1%，全部集中于 #11）|

> **关于 F4**：初版曾把"预算耗尽降级"列为失败模式 F4。它是**结局**而非**病因**，故已从根因轴移除，归入 S3。

### 4.2 根因轴（Root Causes）

| 编号 | 失败模式 | 机制 | 代表案例 | 谁才能发现它 |
|---|---|---|---|---|
| **F1** | 结构歧义 (Structural Ambiguity) | 输入含复数实体，诱导模型输出 JSON 数组而非对象 | #11 A 组（3/3） | 规则自动拦截（`STRUCTURE_root_shape`） |
| **F2** | 示例占位符约束锁死 (Placeholder Lock-in) | 防幻觉占位符无法示范生成型修复，四重指令剥夺可执行解空间 | #11 B 组（3/3） | **必须人工看 `feedbackPrompt`** |
| **F3** | 评测集标注争议 (Ground Truth Ambiguity) | 两组 × 三次 100% 一致与 GT 冲突 | #6、#8（各 6/6） | **人工跨组一致性比对** |
| **F5** | 模型采样随机方差 (Sampling Variance) | 同输入跨轮次结果翻转 | #7、#12 A 组（各 1/3） | Repetition 重复实验 |
| **★ F6** | 语义错误被合规性掩盖 (Semantic Masking) | 自愈修复了次生违规，同时把原生语义错误固化并合法化验收 | #7 B 组（3/3） | **合规率 × 语义准确率交叉比对** |

## 六、深度病理解剖

### 6.1 ★ F6：Case #7 与 −7.1pt 语义退化

**输入**：`订单号 ORD-443322 还没收到货怎么就签收了？如果是丢件了就赶紧给我退款！`  
**GT**：`category = refund`

| | R1 | R2 | 结果 |
|---|---|---|---|
| **A 组** | `refund` + `urgency≥4` ✅语义正确 | — | 2/3 因 summary 过短失败，**但语义正确 3/3** |
| **B 组** | `logistics` ❌语义错误 + `urgency=5` → 被 L2 拦截 | `urgency 5→3` → 合规通过 | **合规 3/3 PASS，语义 0/3** |

**病理**：
> 校验器只知道"logistics ⇒ urgency ≤ 3"，它不知道用户真正想要的是退款。
> 自愈忠实地完成了本职工作——把不合规的对象修成合规的对象；代价是**把一个语义错误的分类合法化了**。

**根因层**：`category = logistics` 不违反任何契约规则——"正确答案应是 refund"这件事**只有 ground truth 知道，校验器无从得知**。自愈的验收判据是"通过校验器"，而非"语义正确"。

> **这是当前架构的已知边界，不是 bug**：规则只能校验规则内的违规，规则外的正确性必须由 ground truth 或 judge 覆盖。

**一个待验证的假设**：A 组在 R1 判对（refund），B 组在 R1 判错（logistics），而两组共用同一份系统提示词——**差异只可能来自 L1 约束解码或 schema description**。建议实验 E0：B 组关闭 `response_format`（仅保留 schema 校验），观察 #7 的 category 是否回到 `refund`。若成立，则说明受限解码会改变首轮语义选择，这是比 F6 更底层的发现。

### 6.2 F2：Case #11 与黄金示例的防幻觉 Trade-off

**输入**：`我有两个订单，ORD-111111 上个星期已经退款完成了，ORD-222222 的保温杯内胆生锈，这个我要申请退款。`

#### (1) 可行解客观存在，规则集并无矛盾

```json
{ "urgency": 4, "category": "refund",
  "summary": "保温杯内胆生锈严重，用户要求退款处理",
  "orderId": "ORD-222222" }
```
18 字、无单号复述、四条约束全满足 → **"规则自相矛盾"的定性被证伪**。

#### (2) 真实病根：R2 的 `feedbackPrompt` 四重指令锁死

```json
【1. 结构对齐示例 Golden Exemplar】
{ "urgency": 4, "category": "refund",
  "summary": "示例占位值示例占位值示例占位值示例占位值",
  "orderId": "ORD-222222" }
注意：示例中的占位值仅为格式示范，严禁照抄为真实数据
```

模型在该轮同时收到四条指令：

| 指令 | 效果 |
|---|---|
| summary 必须 ≥ 15 字 | 要求改 |
| summary 不得复述订单号 | 限制改法 |
| **禁止局部微调** | 禁止改法 |
| **示例严禁照抄** | 禁止唯一的示范解法 |

**两条要求它改，两条禁止它改 → 唯一合法动作是原地不动。**
R2 与 R3 输出**逐字相同**，说明 R2 升级机制**没有达成它自己"打破同构重试"的设计目的**。

#### (3) 机制根因

`structured-output.ts:744` 的 invariant 确立了两条正确设计：
- **不凭空编造具象实体值**（防幻觉，有单测守卫）
- **不沿用上一轮输出**（防字段冻结，`article-03` 已踩过此坑）

二者叠加的结果：示例只能是无信息量的占位符。而：

| 场景 | 修复类型 | 占位符够用吗 | 结果 |
|---|---|---|---|
| #13 数值 5→3 | 收敛型 | 够（只示范格式） | ✅ 3/3 |
| #11 字数 11→15 | 生成型 | **不够**（需要真实内容） | ❌ 0/3 |

> **防幻觉的代价，在生成型修复上表现为自愈能力的丧失。**这是一个 trade-off，不是 bug。

### 6.3 F3：Case #6、#8 与"先怀疑标签"法则

| case | 实际输入要点 | GT | 模型输出（A/B 各 3 次，共 6 次） |
|---|---|---|---|
| **#6** | 订单刚签收，**找不到说明书**，求发电子版 | `other` | **6/6 一致输出 `quality`** |
| **#8** | 快递箱全压扁，**里面的杯子碎了**，需要处理 | `logistics` | **6/6 一致输出 `quality`** |

> **试金石法则**：当模型在**不同组别（A/B）× 多次采样（3 次）**下均以 **100% 一致性**违背 GT 时，首先应当质疑 **GT 的定义合理性**，而非模型的理解力。

**#6 与 #8 都是混合诉求**，单一归类本身可议：
- #6：附件/资料缺失 → 既非商品质量瑕疵，也非物流，GT 的 `other` 可成立，但模型稳定地把它理解成"商品附件不全 = 质量"，说明**分类定义需要显式消歧规则**。
- #8：外箱破损（物流）+ 内容物碎裂（质量）→ GT 取 `logistics`、模型取 `quality`，两者均有理由。

**#11 不是 F3**：实测 `orderIdAccuracy` 双组均为 **100%**（三次全中 `ORD-222222`），不存在抽取层面的实质冲突。初版把 #11 列为 F3 代表案例，**已更正为"潜在的定义不严谨，未造成任何失败"**。

### 6.4 F5：消灭生产方差（Case Stability）

| 组别 | 稳定通过 3/3 | 稳定失败 0/3 | **随机抖动** | Case 级稳定性 |
|---|---|---|---|---|
| **A 组** | 10 | 2（#3、#11） | **2（#7、#12）** | **85.7%** |
| **B 组** | 13 | 1（#11） | **0** | **100%** |

> 在工业落地中，**"准确且可复现"比"平均准确但每次不一样"更有决策价值**。
> B 组通过契约守卫与自愈循环把采样抖动完全吸收——这是本次实验**被主指标掩盖的第二项成果**。

### 6.5 F1：Case #11 A 组的结构歧义

输入含"我**有两个订单**"→ A 组 3/3 输出 **JSON 数组** `[{...}]` → `STRUCTURE_root_shape`。

这不是模型不理解字段，而是**自然语言中的复数实体诱发了根类型分歧**。B 组因 L1 强制 object 约束，**此类错误降至 0**。这是 L1 最干净的一次胜利。

## 七、改进路线（按依赖与变量隔离排序）

### 7.1 治 F2：落地 `groundedInInput` 溯源原语 — **最高优先级**

- **方案**：`generateGoldenExemplar(schema, { sourceText: userInput })`
- **机制**：示例中待修复字段的值**从原始输入文本中抽取**（"保温杯/内胆/生锈/退款"），而非占位符，也非沿用上一轮。
  - 既不幻觉（值可溯源到输入）
  - 也不冻结（不沿用错误的上一轮）
  - 且自带真实内容（能示范"如何从 11 字扩到 15 字"）
- **通用性检验**：拿去做"法律合同审查工作流"需要改吗？不需要——合同编号同样从合同文本抽取。**符合引擎架构纯度铁律**（非业务特例，是可复用原语）。
- **验证判据**：#11 由 0/3 → ≥2/3 通过；其余 13 个用例无退化。

### 7.2 治 F6：语义消歧必须在 **R1 层面** 干预

> ⚠️ **初版方案"在自愈提示词里加'严禁篡改 category'"打错了位置**：#7 的 category 错误发生在 **R1**，此时还没有任何自愈反馈，R2+ 的提示词影响不到它。而且"禁止修改"正是 `article-03` 已经踩过的**字段冻结陷阱**。

- **正确方案**：在 **schema 的 `category` 描述**中写入消歧规则（如"按用户核心诉求归类：明确要求退款即为 `refund`，即便同时涉及物流"）。
  - 作用于 R1（错误发生的地方）
  - 且**只作用于 B 组**（A 组无 schema）→ **变量完美隔离**，不污染基线
  - 理由是 M0 已确立的纪律：**field description 是 prompt 的一部分，是最便宜、最稳定的约束施加点**
- **配套实验 E0**：验证 L1 约束解码是否本身改变了首轮语义选择（见 6.1）。

### 7.3 治 F3：复核 GT

修正 #6、#8 的标签，或在分类契约中补充显式消歧规则。**注意：这不阻塞 7.1 与 7.2**——#6/#8 不影响合规率，且 #11 的失败与 GT 无关。

### 7.4 实验纪律

| 规则 | 说明 |
|---|---|
| **一次只改一个变量** | E1（改 exemplar）、E2（改 category 描述）、E3（改 orderId 描述）必须**分开跑**，否则无法归因 |
| **必须全量重跑** | 只跑 #11 只能证明"修好了一个"，证明不了"没弄坏别的"——#7 已证明退化真实存在。**M1 里"回归"的定义就是全量重跑 + 逐项对比** |
| **先用 SIMULATION** | 零成本验证 harness 改动无误后，再切 live |
| **成本量级** | 全量一次 84 次调用 ≈ 5.5 万 tokens |

## 八、结论表述模板（限定口径，可直接引用）

> 引入结构化输出与自愈状态机后，端到端契约合规率由 69.0% 提升至 92.9%（按样本配对 McNemar p < 0.01，+23.9pt），其中 L1 受限解码贡献 +4.8pt、L3 自愈状态机贡献 +19.0pt；用例级输出稳定性由 85.7% 提升至 100%，消除了采样方差；代价为平均 token 消耗 ×2.90。
>
> **同时观测到意图分类准确率由 85.7% 降至 78.6%（−7.1pt）**：自愈的验收判据是"通过校验器"而非"语义正确"，规则外的语义错误无法被拦截，反而可能被自愈合法化（F6）。这是当前架构的已知边界，也是下一轮的主要改进方向。
>
> 结论按独立用例口径尚未达显著（b=4、c=0，p=0.125 为 n=4 的数学下限），需扩充用例数至产生 ≥6 个 discordant 后方可在用例层面做显著性断言。

> **主动披露退化指标，是这份报告可信度最高的部分。**评审者看到你会自己报告 −7.1pt，才会相信你的 +23.9pt。

## 九、已知局限

| # | 局限 | 影响 |
|---|---|---|
| 1 | 数据集仅 14 个用例，全部**人工合成**，且集中于单一业务域 | 场景覆盖不足，用例层面未达显著 |
| 2 | 仅测试**单个模型**（Qwen2.5-7B-Instruct） | 结论不可直接外推至其他模型或尺寸 |
| 3 | 无 LLM judge，规则外质量维度仅由 GT 覆盖 `category` / `orderId` 两维 | `summary` 的语义质量（是否准确复述诉求、是否幻觉）**完全未被度量** |
| 4 | 无数据集增长机制 | 修一个 bug 未对应新增一个用例 |
| 5 | 未固化 baseline，无 CI 回归 | 无法一条命令回答"这次改动是否退步" |
