## 〇、摘要卡：四个指标必须同时报告

单一指标会掩盖维度退化。本报告的全部结论建立在以下四类指标之上：

| 类别 | 指标 | A 组 | B 组 | 变化 |
|---|---|---|---|---|
| **合规** | 端到端契约合规率 | 69.0% (29/42) | 92.9% (39/42) | **+23.9pt** |
| **正确性** | 意图分类（category）准确率 | 85.7% (36/42) | 78.6% (33/42) | **−7.1pt** ⚠️ |
| **正确性** | 订单号（orderId）准确率 | 100% | 100% | — |
| **稳定性** | 用例级输出稳定性 | 85.7% (12/14) | 100% (14/14) | **+14.3pt** |
| **成本** | 平均 token 消耗 | 333 | 966 | **×2.90** |
| **成本** | 每修好一样本的边际成本 | — | 2658 tok | — |

> **本文最重要的一句话**：合规率 +23.9pt 的同时，语义准确率 −7.1pt。**这两个数字必须同时出现**，只报前者是不完整的结论。
>
> **更新（E2 实验，§6.7）**：在 `category` description 中加入语义消歧规则后，B 组 category 准确率由 78.6% 回升至 **92.9%（+14.3pt）**、合规率升至 **98.2%**，且未反向伤害 GT 为 `logistics` 的 #2/#13；代价是稳定性降至 92.9%、成本 +33.6%。**F2 的根因未被触动（本次未触发到示例升级），仍需独立修复。**
>
> **更新（E0b 实验，§6.8）—— 因果闭合**：置换 enum 顺序后，14 个用例的 category 判定**逐用例与基线完全同构（14/14）**，#7 仍是 0/4 `logistics`。**「枚举首因效应」假说被三个方向同时证伪**；F6 根因唯一收敛到 **category description 过弱**。
>
> E0b 的更大价值是它**无意中成为 E2 的阴性对照（placebo）**：它也改了 Schema，收益 **0.0pt**；E2 改的是 description，收益 **+14.3pt**。⇒ 收益来自**消歧语义内容本身**，不是"动了 Schema 就有效"。
>
> 统计上，E0b 把 #7 的证据由单独 0/3 vs 4/4（Fisher 两尾 **p = 0.0286**）**合并为 0/7 vs 4/4（p = 0.0030）**。
>
> **F2 状态由「未验证」升级为「已复现」**：E0b 下 #11 的 4/4 **全部触发 R2 黄金示例升级**并卡死（合并 7/7 vs E2 0/4，Fisher 两尾 **p = 0.0030**）。且 trace 显示 R2 与 R3 输出**字节级相同**——这是**卡死（fixed point）**，不是振荡；#3 才是振荡（13→31→14 字）。两种形态修法不同，见 §6.8.4。

## 一、方法：实验设计与数据来源

### 1.1 实验配置

| 项 | 值 |
|---|---|
| 模型 | Qwen/Qwen2.5-7B-Instruct（SiliconFlow） |
| 温度 | 0.2 |
| 数据集 | 14 个用例（10 easy + 4 adversarial）|
| 重复次数 | 基线 3 → 每组 42 个样本；E0b / E2 为 4 → 每组 56 个样本 |
| A 组 | 仅 prompt 约束（无 schema、无自愈） |
| B 组 | L1 受限解码 + L2 Zod 契约校验 + L3 自愈状态机 |
| 变量隔离 | `UNIFIED_SYSTEM_PROMPT` 两组完全相同（`run-siliconflow-ab-test.ts:129`） |

### 1.2 两条正确的方法论设计（值得保留）

1. **Ground truth 不喂给校验器**：`expectedCategory` / `expectedOrderId` 仅用于正确性度量，绝不参与契约校验——避免"用答案证明答案"的自证循环。
2. **系统提示词两组统一**：保证 A/B 的唯一变量是"结构化输出与自愈机制"本身。

### 1.3 统计口径

- 配对 **McNemar 精确检验**，双口径；Wilson 95% 置信区间
- **按样本**（n=42）：p = 0.00195 ✅ 显著
- **按独立用例**：b=4（A 败 B 胜：#3、#7、#12、#13）、c=0 → **p = 0.125** ⚠️
- **关键澄清**：b=4、c=0 时 p 的**数学最小值就是 0.125**（2 × 0.5⁴）。这不是"效果不确定"，而是 **n=4 的样本量上限**。要达到 p < 0.05，至少需要 **6 个 discordant 且全为 b**（6:0 → p = 0.0313）。
- → 行动项是**扩用例数**，不是加 repetition。repetition 度量"模型不确定性"，用例数度量"场景覆盖"，两者不可互换。

## 二、成功切片：先理解自愈为何有效，才能界定它的边界

**分析失败前先看成功**——因为只有知道自愈"为什么能修好"，才能判断它"什么时候修不好"。

### 2.1 主证：Case #13（激烈情绪的物流投诉）

- **输入**：`订单号 ORD-333333 的包裹卡在中转站整整三天没有任何动静了，客服电话打了五遍都没人接，我非常愤怒，必须马上给我一个说法！`
- **GT**：`category = logistics`
- **A 组**：3/3 输出 `urgency = 5` → 触发跨字段契约「logistics ⇒ urgency ≤ 3」→ **0/3 全灭**
- **B 组 trace**：

```
R1  urgency=5, category=logistics, summary="包裹中转站滞留多日，客服电话无法接通。"
    → L2 拦截：「物流类工单不涉及资金流转，urgency 必须 ≤ 3」
    → 处方同时给出：category 与 urgency 任意一个都可改，请判断哪个判断错了
R2  urgency=3, 其余字段不变 → 通过   ✅ 3/3 全数自愈
```

### 2.2 机制：收敛型修复 vs 生成型修复

| 修复类型 | 需要的动作 | 自愈能否完成 | 例 |
|---|---|---|---|
| **收敛型** | 从已有信息中**删除 / 收敛 / 调整** | ✅ 能 | #13 数值 5→3；#1/#3 字数补足 |
| **生成型** | 必须**产生新的、有信息量的内容** | ❌ 不能 | #11（见 F2） |

> **自愈的有效性边界**：它能修"改一下就行"的违规，修不了"得新写点东西"的违规。这条边界决定了后面所有失败模式的走向。

### 2.3 B 组成功构成

| 构成 | 数量 | 占比 |
|---|---|---|
| 首轮直接通过（S1） | 31 | 73.8% |
| 被 L2 拦截 | 11 | 26.2% |
| — 其中自愈救回（S2） | 8 | 19.0% |
| — 其中降级托底（S3） | 3 | 7.1% |

## 三、精确归因（可复算口径）

```
Baseline (A)          69.0%  (29/42)
   │
   ├─ L1 受限解码 + Schema 注入（首轮通过 29→31）   +4.8pt
   ▼
B 组首轮 (S1)          73.8%  (31/42)
   │
   ├─ L3 自愈状态机救回 8 个样本                    +19.0pt
   ▼
B 组最终               92.9%  (39/42)
```

**自愈贡献 19.0pt，L1/提示词贡献 4.8pt。**端到端提升主要来自自愈，而非"模型首轮犯错变少"——这一点与直觉相反，值得在结论中明确。

**成本对应**：A 333 tok → B 966 tok（**×2.90**），延迟 2465ms → 2857ms（+16%）。**每修好一个样本的边际成本为 2658 tokens。**

## 四、双轴正交分析框架

> **严禁把"终止状态"与"失败根因"并列。**二者不在同一根轴上：每一个根因失败最终都以某个终止状态收场，并列会导致重复计数与分类交叉。

### 4.1 终止状态轴（Termination States）

| 编号 | 状态 | 定义 | B 组分布 |
|---|---|---|---|
| **S1** | 首轮直通 | 首轮即通过 L1 + L2 | 31/42（73.8%） |
| **S2** | 自愈收敛 | 首轮被 L2 拦截，L3 反馈后修正通过 | 8/42（19.0%） |
| **S3** | 降级托底 | 3 次调用预算耗尽，L4 Never-Throw 返回 `_validationFailed` | 3/42（7.1%，全部集中于 #11）|

> **关于 F4**：初版曾把"预算耗尽降级"列为失败模式 F4。它是**结局**而非**病因**，故已从根因轴移除，归入 S3。

### 4.2 根因轴（Root Causes）

| 编号 | 失败模式 | 机制 | 代表案例 | 谁才能发现它 |
|---|---|---|---|---|
| **F1** | 结构歧义 (Structural Ambiguity) | 输入含复数实体，诱导模型输出 JSON 数组而非对象 | #11 A 组（3/3） | 规则自动拦截（`STRUCTURE_root_shape`） |
| **F2** | 示例占位符约束锁死 (Placeholder Lock-in) | 防幻觉占位符无法示范生成型修复，四重指令剥夺可执行解空间 | #11 B 组（3/3） | **必须人工看 `feedbackPrompt`** |

## 六、深度病理解剖

### 6.1 ★ F6：Case #7 与 −7.1pt 语义退化

**输入**：`订单号 ORD-443322 还没收到货怎么就签收了？如果是丢件了就赶紧给我退款！`
**GT**：`category = refund`

| | R1 | R2 | 结果 |
|---|---|---|---|
| **A 组** | `refund` + `urgency≥4` ✅语义正确 | — | 2/3 因 summary 过短失败，**但语义正确 3/3** |
| **B 组** | `logistics` ❌语义错误 + `urgency=5` → 被 L2 拦截 | `urgency 5→3` → 合规通过 | **合规 3/3 PASS，语义 0/3** |

**病理**：
> 校验器只知道"logistics ⇒ urgency ≤ 3"，它不知道用户真正想要的是退款。
> 自愈忠实地完成了本职工作——把不合规的对象修成合规的对象；代价是**把一个语义错误的分类合法化了**。

**根因层**：`category = logistics` 不违反任何契约规则——"正确答案应是 refund"这件事**只有 ground truth 知道，校验器无从得知**。自愈的验收判据是"通过校验器"，而非"语义正确"。

> **这是当前架构的已知边界，不是 bug**：规则只能校验规则内的违规，规则外的正确性必须由 ground truth 或 judge 覆盖。

**一个待验证的假设**：A 组在 R1 判对（refund），B 组在 R1 判错（logistics），而两组共用同一份系统提示词——**差异只可能来自 L1 约束解码或 schema description**。建议实验 E0：B 组关闭 `response_format`（仅保留 schema 校验），观察 #7 的 category 是否回到 `refund`。若成立，则说明受限解码会改变首轮语义选择，这是比 F6 更底层的发现。

### 6.2 F2：Case #11 与黄金示例的防幻觉 Trade-off

**输入**：`我有两个订单，ORD-111111 上个星期已经退款完成了，ORD-222222 的保温杯内胆生锈，这个我要申请退款。`

#### (1) 可行解客观存在，规则集并无矛盾

```json
{ "urgency": 4, "category": "refund",
  "summary": "保温杯内胆生锈严重，用户要求退款处理",
  "orderId": "ORD-222222" }
```
18 字、无单号复述、四条约束全满足 → **"规则自相矛盾"的定性被证伪**。

#### (2) 真实病根：R2 的 `feedbackPrompt` 四重指令锁死

```json
【1. 结构对齐示例 Golden Exemplar】
{ "urgency": 4, "category": "refund",
  "summary": "示例占位值示例占位值示例占位值示例占位值",
  "orderId": "ORD-222222" }
注意：示例中的占位值仅为格式示范，严禁照抄为真实数据
```

模型在该轮同时收到四条指令：

| 指令 | 效果 |
|---|---|
| summary 必须 ≥ 15 字 | 要求改 |
| summary 不得复述订单号 | 限制改法 |
| **禁止局部微调** | 禁止改法 |
| **示例严禁照抄** | 禁止唯一的示范解法 |

**两条要求它改，两条禁止它改 → 唯一合法动作是原地不动。**
R2 与 R3 输出**逐字相同**，说明 R2 升级机制**没有达成它自己"打破同构重试"的设计目的**。

#### (3) 机制根因

`structured-output.ts:744` 的 invariant 确立了两条正确设计：
- **不凭空编造具象实体值**（防幻觉，有单测守卫）
- **不沿用上一轮输出**（防字段冻结，`article-03` 已踩过此坑）

二者叠加的结果：示例只能是无信息量的占位符。而：

| 场景 | 修复类型 | 占位符够用吗 | 结果 |
|---|---|---|---|
| #13 数值 5→3 | 收敛型 | 够（只示范格式） | ✅ 3/3 |
| #11 字数 11→15 | 生成型 | **不够**（需要真实内容） | ❌ 0/3 |

> **防幻觉的代价，在生成型修复上表现为自愈能力的丧失。**这是一个 trade-off，不是 bug。

### 6.3 F3：Case #6、#8 与"先怀疑标签"法则

| case | 实际输入要点 | GT | 模型输出（A/B 各 3 次，共 6 次） |
|---|---|---|---|
| **#6** | 订单刚签收，**找不到说明书**，求发电子版 | `other` | **6/6 一致输出 `quality`** |
| **#8** | 快递箱全压扁，**里面的杯子碎了**，需要处理 | `logistics` | **6/6 一致输出 `quality`** |

> **试金石法则**：当模型在**不同组别（A/B）× 多次采样（3 次）**下均以 **100% 一致性**违背 GT 时，首先应当质疑 **GT 的定义合理性**，而非模型的理解力。

**#6 与 #8 都是混合诉求**，单一归类本身可议：
- #6：附件/资料缺失 → 既非商品质量瑕疵，也非物流，GT 的 `other` 可成立，但模型稳定地把它理解成"商品附件不全 = 质量"，说明**分类定义需要显式消歧规则**。
- #8：外箱破损（物流）+ 内容物碎裂（质量）→ GT 取 `logistics`、模型取 `quality`，两者均有理由。

**#11 不是 F3**：实测 `orderIdAccuracy` 双组均为 **100%**（三次全中 `ORD-222222`），不存在抽取层面的实质冲突。初版把 #11 列为 F3 代表案例，**已更正为"潜在的定义不严谨，未造成任何失败"**。

### 6.4 F5：消灭生产方差（Case Stability）

| 组别 | 稳定通过 3/3 | 稳定失败 0/3 | **随机抖动** | Case 级稳定性 |
|---|---|---|---|---|
| **A 组** | 10 | 2（#3、#11） | **2（#7、#12）** | **85.7%** |
| **B 组** | 13 | 1（#11） | **0** | **100%** |

> 在工业落地中，**"准确且可复现"比"平均准确但每次不一样"更有决策价值**。
> B 组通过契约守卫与自愈循环把采样抖动完全吸收——这是本次实验**被主指标掩盖的第二项成果**。

### 6.5 F1：Case #11 A 组的结构歧义

输入含"我**有两个订单**"→ A 组 3/3 输出 **JSON 数组** `[{...}]` → `STRUCTURE_root_shape`。

这不是模型不理解字段，而是**自然语言中的复数实体诱发了根类型分歧**。B 组因 L1 强制 object 约束，**此类错误降至 0**。这是 L1 最干净的一次胜利。

#### 6.8.2 三向证伪：为什么可以下结论

单次置换能同时检验三个方向，这比只跑一个方向强得多：

| 方向 | 操作 | 若首因效应成立应看到 | 实测 | 裁决 |
|---|---|---|---|---|
| **① 剥夺** | `logistics` 由首位 → 末位 | #7 应脱离 `logistics` | #7 仍 4/4 `logistics` | ❌ 证伪 |
| **② 授予** | `refund` 由第二位 → 首位 | #7 应被拉向 `refund` | #7 仍 0/4 `refund` | ❌ 证伪 |
| **③ 抗性** | `logistics` 由首位 → 末位 | #2/#13（GT=logistics）有误判风险 | 仍 4/4 `logistics` | ❌ 证伪 |

方向 ② 尤其关键：**它排除了"#7 判错只是因为 refund 没占到首位"这一替代解释**——我们把首位直接送给了 `refund`，#7 依然不选它。

> **严格表述**：在 14 用例 × 4 轮、temperature 0.2 条件下，**未观测到 enum 顺序对 category 判定的任何影响（14/14 用例判定同构）**。
> **不宜表述**："位置偏差不存在"。本结论的适用边界是：Qwen2.5-7B-Instruct、4 值 enum、字段有明确语义锚点的场景。位置偏差在更长枚举、更弱语义锚点、更小模型上仍然可能成立。

#### 6.8.3 ★ 意外收获：E0b 是 E2 的阴性对照（placebo control）

这是本次实验最有方法论价值的一点。

| 实验 | 改了什么 | 是否改动 Schema | category 收益 |
|---|---|---|---|
| **E0b** | enum **顺序** | ✅ 改了 | **0.0pt**（78.6% → 78.6%） |
| **E2** | category **description 内容** | ✅ 改了 | **+14.3pt**（78.6% → 92.9%） |

两次实验**都动了 Schema**，但只有改 description 的那次产生了收益。

> **推论：E2 的 +14.3pt 可以归因于「消歧语义内容」本身，而不是"我修改了 Schema 所以看起来有效"的安慰剂效应。**
>
> 这条推论很重要，因为 LLM 评测里最常见的自欺就是：改一堆东西 → 指标涨了 → 归功于自己想改的那一项。阴性对照是唯一能挡住它的手段。

**同时，E0b 为 #7 增加了 4 个独立观测，使证据可以合并：**

| 对比 | 数据 | Fisher 精确检验（两尾） |
|---|---|---|
| 基线 vs E2 | #7: 0/3 → 4/4 | p = 0.0286 ✅ 已显著 |
| E0b vs E2 | #7: 0/4 → 4/4 | p = 0.0286 |
| **基线 + E0b 合并 vs E2** | **#7: 0/7 → 4/4** | **p = 0.0030** ✅ |

> **⚠️ 一处自我更正**：我最初写"基线 vs E2 的 p = 0.0571（边缘）"，**这是错的**。实算得 **p = 0.0286**。
> 原因是 Fisher 两尾检验按"概率 ≤ 观测概率"求和，而在**两组样本量不等**（3 vs 4）时，另一侧的极端情形概率为 0.1143 > 0.0286，**不计入**，故 p 只有单侧那一项。
> ⇒ 不等组样本量的 Fisher 两尾 p 可能与更大的等组设计**相同**（3v4 与 4v4 都是 0.0286），**不能凭直觉估 p，必须实算**。
>
> E0b 的真实统计贡献不是"把边缘推成显著"（它本来已显著），而是**提供了 4 个额外的独立观测**，使合并证据从 0/3 变为 0/7，p 由 0.0286 降至 **0.0030**。

#### 6.8.4 ★ F2 状态升级：从「未验证」到「已复现」，且形态被精确界定

E0b 中 #11 的 4 轮**全部触发 R2 黄金示例升级**（基线 3/3 + E0b 4/4 = **7/7**；E2 中 0/4，Fisher 两尾 **p = 0.0030**），F2 被完整复现。对比两次实验的 trace：

```
E0b  #11（F2 复现）          E2   #11（F2 被绕过）
R1  "ORD-222222 保温杯内胆生锈，要求退款"  23字 ✗ 含订单号    R1  "保温杯内胆生锈，要求退款"              12字 ✗ <15
R2  "保温杯内胆生锈，要求退款"            12字 ✗ <15        R2  "保温杯内胆生锈严重，多次联系客服未果…"  27字 ✓ 通过
R3  "保温杯内胆生锈，要求退款"            12字 ✗ <15        （未用到 R3）
    ↑ 与 R2 字节级相同
```

**决定性观察：R2 与 R3 输出完全相同。**

这不是"振荡"（上下跳动），而是**卡死（fixed point）**——模型收到黄金示例 + 处方后，原样复述上一轮，说明**这一轮交互没有向模型注入任何新信息**。

据此必须把生成型修复的失败**拆成两种形态**，此前笼统称为"振荡"是不精确的：

| 形态 | 代表 | trace 特征 | 模型的实际状态 | 对症修法 |
|---|---|---|---|---|
| **卡死（fixed point）** | #11 | 连续轮次输出**字节级相同** | **不知道该写什么**——信息被删掉后没有补充来源 | **注入新信息**：`groundedInInput` 从原始输入抽取素材 |
| **振荡（oscillation）** | #3（E2） | 13字 → 31字 → 14字，每轮都在动但每次撞另一边墙 | **有能力写**（31 字证明）但**没有目标锚点** | **给出区间锚点**：示例应落在区间中部（~20 字），而非只说"≥15" |

> #3 在 E2 中的 trace 是教科书的振荡：`13字(不足) → 31字(超上限) → 14字(又不足) → 降级`。
> 它证明模型**能写出 31 字**，所以 #3 的问题不是能力，是**目标不可见**。

这个区分直接支撑 §7.1：`groundedInInput` 对 #11 是**对症**的——#11 的原始输入里"保温杯 / 内胆生锈 / 客服未回应 / 要求退款"素材充足，模型只是删掉订单号后不知道用什么补位。**"不知道补什么"正是"没有可溯源素材"的定义。**

#### 6.8.5 ★ 一个必须承认的变量隔离边界：description 改动是非局部的

E2 只改了 `category` 一个字段的 description，但 #11 的 **R1 输出也变了**：

```
基线/E0b #11 R1: "ORD-222222 保温杯内胆生锈，要求退款"   ← 复述了订单号
E2       #11 R1: "保温杯内胆生锈，要求退款"              ← 不再复述
```

> **这意味着：E2 并不是"修好了 F2"，而是"改变了 R1 的失败类型，从而绕过了 F2 的触发条件"。**
> 一个字段描述的改动，**溢出影响到了另一个字段（summary）的生成行为**。

由此得出一条对 LLM 实验根本重要的认识：

> **在 LLM 上，单变量隔离只能是「声明式单变量」（只改一处声明），无法保证「行为单变量」（只影响一处行为）。**
> 这是 LLM 实验与经典 A/B 实验的根本差异——模型是一个整体条件分布，改任何一处 prompt 都会重新加权整个输出。
>
> 实践含义：**不能因为"我只改了一处"就假定其他指标未受影响；必须靠哨兵监控 + 逐用例回归来兜底**。这正是 §6.8 开头那条 Watch-List 存在的理由。

#### 6.8.6 A 组噪声警告：合规率提升无法与噪声分离

A 组在三次实验中都不受任何变体影响（恒定对照），理论上应完全一致：

| 实验 | A 组合规率 | A 组 category |
|---|---|---|
| 基线（n=42） | 69.0% | 85.7% |
| **E0b（n=56）** | **58.9%** | 84.3% |
| E2（n=56） | 69.6% | 85.2% |

A 组合规率的跨度是 **10.7pt**，而 B 组端到端合规率的跨实验差异只有 **5.3pt**（92.9% → 98.2%）。

> **⚠️ 因此：B 组「端到端合规率 +5.3pt」这一项落在恒定对照自身的噪声带内，不能与噪声分离，不应作为独立结论引用。**
>
> 相反，category 准确率的提升（**+14.3pt**）远超 A 组在该指标上的噪声（84.3%–85.7%，跨度仅 1.4pt），且 #7 / #6 是完全分离（合并 0/7 → 4/4，**p = 0.0030**）。
> **⇒ 可以下的结论是「语义准确性真实提升」；不能下的是「合规率显著提升」。**

#### 6.8.7 为什么顺序无效而描述有效 —— 一个可迁移的概念

三个实验合起来给出了一条关于 LLM 决策层级的观察：

```
强指令（field description 中的判据）  >  表层词汇最近邻  >  位置先验（enum 顺序）
```

- **有判据时**：模型按判据走（E2 的 #7 → refund）
- **无判据时**：模型**回退到输入文本的表层词汇**，而不是回退到位置（基线/E0b 的 #7 文本被"物流 / 签收"主导 → logistics）
- **位置先验**：在本实验中**从未成为决定性因素**（三向证伪）

> 可迁移形态：**当 Schema 字段缺少语义判据时，模型会用输入文本的表层词汇做映射；补齐判据优先于调整结构（顺序 / 格式）。**
> 拿去做"法律合同审查工作流"同样成立：把 `contractType` 的 enum 重排不会改善分类，写清"以合同实质义务判定，而非标题措辞"才会。

## 七、改进路线（按依赖与变量隔离排序）

### 7.1 治 F2：落地 `groundedInInput` 溯源原语 — **最高优先级**

> **优先级依据已由 E0b 坐实（§6.8.4）**：#11 在 E0b 下 4/4 触发 R2 升级并**卡死**（R2 与 R3 字节级相同）。这不是推测，是复现。

- **方案**：`generateGoldenExemplar(schema, { sourceText: userInput })`
- **机制**：示例中待修复字段的值**从原始输入文本中抽取**（"保温杯/内胆/生锈/客服未回应/退款"），而非占位符，也非沿用上一轮。
  - 既不幻觉（值可溯源到输入）
  - 也不冻结（不沿用错误的上一轮）
  - 且自带真实内容（能示范"如何从 12 字扩到 15+ 字"）
- **为什么对症**：#11 的失败形态是**卡死**——模型删掉订单号后不知道用什么补位，原始输入里素材充足。卡死的解药是**注入新信息**，不是更强的指令。
- **通用性检验**：拿去做"法律合同审查工作流"需要改吗？不需要——合同编号同样从合同文本抽取。**符合引擎架构纯度铁律**（非业务特例，是可复用原语）。
- **验证判据**：#11 由 0/4 → ≥3/4 通过；其余 13 个用例无退化。
- **⚠️ 验证时必须跑 `--e0b-enum-order`（或基线）——不能只跑 E2**：E2 下 #11 的 R2 触发数为 0，用它验证 F2 等于验证了一条从未被执行的路径（§6.7 已犯过一次）。基线 + E0b 下 #11 的 R2 触发为 7/7，是可靠的触发基线。

#### 7.1.1 配套：振荡型失败需要**区间锚点**，与卡死不同药

`groundedInInput` 只解决**卡死**。§6.8.4 界定的**振荡**（#3：13 → 31 → 14 字）需要另一味药：

- 模型**有能力写**（E2 中它写出了 31 字），缺的是**目标区间的可见锚点**。
- 修法：黄金示例的示例值应落在**区间中部**（约 20 字），而非只复述"≥15 且 ≤30"；或在处方中直接给出目标字数与一个落点。
- **判据**：#3 的 4/4 稳定通过，且不引入新的超上限失败。

### 7.2 治 F6：语义消歧必须在 **R1 层面** 干预（E0 已验证方向正确）

> ⚠️ **初版方案"在自愈提示词里加'严禁篡改 category'"打错了位置**：#7 的 category 错误发生在 **R1**，此时还没有任何自愈反馈，R2+ 的提示词影响不到它。而且"禁止修改"正是 `article-03` 已经踩过的**字段冻结陷阱**。

- **正确方案**：在 **schema 的 `category` 描述**中写入消歧规则（如"按用户核心诉求归类：明确要求退款即为 `refund`，即便同时涉及物流"）。
  - 作用于 R1（错误发生的地方）
  - 且**只作用于 B 组**（A 组无 schema）→ **变量完美隔离**，不污染基线
  - 理由是 M0 已确立的纪律：**field description 是 prompt 的一部分，是最便宜、最稳定的约束施加点**
- **配套实验 E0 / E0b**：分别排除 `response_format` 与 enum 顺序两个竞争解释（见 §6.6 / §6.8）。
- **状态**：✅ **已验证**——E2 全量回归下 #7 由 0/3 → 4/4，#2/#13 无反向伤害（哨兵监控全绿）。
- **⚠️ 副作用已知**：description 改动是**非局部**的（§6.8.5），它同时改变了 #11 的 R1 失败类型。合入前需知悉这不是零副作用的改动。

### 7.3 治 F3：复核 GT

修正 #6、#8 的标签，或在分类契约中补充显式消歧规则。**注意：这不阻塞 7.1 与 7.2**——#6/#8 不影响合规率，且 #11 的失败与 GT 无关。

### 7.4 实验纪律

| 规则 | 说明 |
|---|---|
| **一次只改一个变量** | E1（改 exemplar）、E2（改 category 描述）、E3（改 orderId 描述）必须**分开跑**，否则无法归因 |
| **★ 必须有阴性对照** | **（E0b 新增，本项目最重要的一条方法论收获）** 只跑"我期望有效的改动"是不够的——必须再跑一次**同样动了 Schema 但不含有效语义内容**的改动（E0b 置换 enum 顺序即充当此角色）。若对照也涨，说明收益来自安慰剂或噪声。E0b 收益 0.0pt vs E2 +14.3pt，才使归因成立 |
| **必须全量重跑** | 只跑 #11 只能证明"修好了一个"，证明不了"没弄坏别的"——#7 已证明退化真实存在。**M1 里"回归"的定义就是全量重跑 + 逐项对比** |
| **★ 警惕反向伤害** | 任何针对 #7 的修复都可能把 **#2 与 #13（GT 就是 `logistics`）** 带偏成 `refund`。**验证时必须同时盯 #2 / #13 的 category** —— 现已固化为 harness 内置的**哨兵监控 Watch-List**（运行前声明，漂移即标红，写入 artifact 的 `sentinel.verdict`） |
| **★ 恒定对照的噪声就是显著性门槛** | A 组不受任何变体影响，其跨实验波动即为噪声底噪。实测 A 组合规率跨度 **10.7pt**，而 B 组跨实验差异仅 5.3pt ⇒ **该项不可与噪声分离，不得引用**。凡引用跨实验差值，先与 A 组噪声带比一比 |
| **★ 声明式单变量 ≠ 行为单变量** | 只改一处 prompt/描述，模型仍可能改变其他字段的生成（§6.8.5 中改 category 描述导致 summary 的 R1 输出变化）。**不能靠"我只改了一处"推断其他指标未受影响**，必须靠哨兵 + 逐用例回归兜底 |
| **p 值必须实算，禁止凭直觉估** | 3 vs 3 完全分离 p = 0.1（不显著），4+4 才达 0.0286。**但不等组时会反直觉**：3v4 与 4v4 完全分离的 Fisher 两尾 p **都是 0.0286**（不等组时另一侧尾部概率大于观测值、不计入）。本项目曾据此写错一次，已更正（§6.8.3） |
| **多轮可合并以强化证据** | E0b 的价值不是"把边缘推成显著"，而是给 #7 增加 4 个独立观测，合并为 0/7 vs 4/4，p 由 0.0286 降至 **0.0030** |
| **先用 SIMULATION** | 零成本验证 harness 改动无误后，再切 live |
| **成本量级** | 全量一次（14 × 4 × 2 组）112 次调用 ≈ 7 万 tokens，约 6 分钟 |

### 7.5 治无 CI 回归门禁：实装自动化防退化门禁与黄金基线快照

为解决「无法一条命令回答这次改动是否退步」的工程断点，评测流水线已正式实装基于黄金快照的自动化回归门禁：

#### 7.5.1 黄金基线快照（`eval-results/baseline.json`）
将已验证收敛的 E2 实验（56 组配对样本全量运行）固化为机器可读的黄金基准快照，解除 gitignore 限制并作为版本资产纳入 Git 版本追踪（`!eval-results/baseline.json`）。该快照永久锁定以下指标基准：
- **契约合规交付率**：98.2%
- **意图分类准确率**：92.9%
- **平均 Token 成本**：1291 tok
- **用例级向量状态**：14 个用例的每一项通过率、意图正确率与历史输出分布；
- **哨兵仲裁结果**：`ALL_GREEN`。

#### 7.5.2 哨兵防漂移双重防御机制（Anti-Drift Guardrails）
针对「外部修改用例库导致下标错位、哨兵静默失效」的隐性工程隐患，实现双重防呆：
1. **语义唯一标识绑定**：每个 Case 强制绑定 `semanticKey`（如 `logistics_query`、`refund_unreceived_signed`、`logistics_angry_complaint`），哨兵监控根据业务语义而非脆弱的数组下标进行绑定；
2. **Fail-Fast 契约自检**：测试脚本在启动执行的第 0 秒（调用 API 之前）执行 `assertSentinelIntegrity`，校验用例 ID、语义 Key、提示词核心关键词以及预期类别是否完全吻合。一旦用例集被重排或篡改，脚本在 1 毫秒内硬性抛错中止，严禁静默错位运行。

#### 7.5.3 差分判定状态机与退出码熔断
在执行 `npm run eval:regression` 时，系统自动读取基线快照并执行逐用例差分计算：
- **`STABLE_PASS`**：基线全过，当前版本依然全过（稳固）；
- **`STABLE_FAIL`**：基线未过，当前版本依然未过（已知历史缺陷，未恶化）；
- **`IMPROVED 🟢`**：基线有瑕疵，当前版本全部通过（有效修复/晋级）；
- **`REGRESSED 🚨`**：**基线原本通过，当前版本发生翻车（硬退化报警）**。

**门禁阻断策略**：
- **硬阻断（Exit Code 1）**：只要检测到任何用例发生 `REGRESSED`、或哨兵名单发生漂移（`COLLATERAL_DAMAGE` / `TARGET_MISSED`）、或全量意图准确率低于基线，终端高亮标红并以退出码 1 阻断 CI；
- **放行（Exit Code 0）**：零退化且核心指标稳固，打印绿灯对账看板并以退出码 0 放行。

#### 7.5.4 标准运行命令
- `npm run eval:baseline`：重新固化并保存当前最新黄金基线至 `eval-results/baseline.json`；
- `npm run eval:regression`：一键全量运行并比对基线，输出回归门禁看板；
- `npm run eval:regression -- --case=N`：靶向针对单个 Case 执行差分回归验证。

## 八、结论表述模板（限定口径，可直接引用）

> 引入结构化输出与自愈状态机后，端到端契约合规率由 69.0% 提升至 92.9%（按样本配对 McNemar p < 0.01，+23.9pt），其中 L1 受限解码贡献 +4.8pt、L3 自愈状态机贡献 +19.0pt；用例级输出稳定性由 85.7% 提升至 100%，消除了采样方差；代价为平均 token 消耗 ×2.90。
>
> **同时观测到意图分类准确率由 85.7% 降至 78.6%（−7.1pt）**：自愈的验收判据是"通过校验器"而非"语义正确"，规则外的语义错误无法被拦截，反而可能被自愈合法化（F6）。这是当前架构的已知边界，也是下一轮的主要改进方向。
>
> 结论按独立用例口径尚未达显著（b=4、c=0，p=0.125 为 n=4 的数学下限），需扩充用例数至产生 ≥6 个 discordant 后方可在用例层面做显著性断言。

**改进实验的结论（E0 / E0b / E2 三件套，可直接引用）：**

> 针对 −7.1pt 的语义退化，我们分离了三个竞争解释并逐一裁决：`response_format` 受限解码（E0，**排除**）、enum 顺序首因效应（E0b，**三向证伪**：14/14 用例判定同构）、`category` 描述过弱（E2，**证实**）。在 `category` 描述中加入消歧判据后，分类准确率由 78.6% 提升至 92.9%（+14.3pt），靶心用例 #7 由 0/7（基线 0/3 + E0b 0/4 合并）提升至 4/4（Fisher 精确检验两尾 **p = 0.0030**）。
>
> 该收益的可信度由一次**阴性对照**支撑：同样修改了 Schema 但只置换 enum 顺序的 E0b 收益为 **0.0pt**。⇒ 收益来自消歧语义内容本身，而非改动 Schema 的安慰剂效应。
>
> **同时披露**：（1）端到端合规率的 +5.3pt **落在恒定对照自身的噪声带内（A 组跨度 10.7pt），不作为结论引用**；（2）该改动具有**非局部效应**，改变了 #11 的首轮失败类型，因此「F2 已被修复」的印象是错觉——F2 在 E2 中根本未被触发（0/4），在 E0b 中被完整复现（4/4 触发并卡死）。F2 仍待独立修复。

> **主动披露退化指标，是这份报告可信度最高的部分。**评审者看到你会自己报告 −7.1pt，才会相信你的 +23.9pt。

## 九、已知局限

| # | 局限 | 影响 |
|---|---|---|
| 1 | 数据集仅 14 个用例，全部**人工合成**，且集中于单一业务域 | 场景覆盖不足，用例层面未达显著 |
| 2 | 仅测试**单个模型**（Qwen2.5-7B-Instruct） | 结论不可直接外推至其他模型或尺寸 |
| 3 | 无 LLM judge，规则外质量维度仅由 GT 覆盖 `category` / `orderId` 两维 | `summary` 的语义质量（是否准确复述诉求、是否幻觉）**完全未被度量** |
| 4 | 无数据集增长机制 | 修一个 bug 未对应新增一个用例 |
| 5 | ~~未固化 baseline，无 CI 回归~~ | **已解决**（§7.5）：已固化 `eval-results/baseline.json`，并支持 `npm run eval:regression` 一键差分对账与 Exit Code 0/1 CI 阻断 |
| 6 | **跨实验噪声大于部分效应量**：恒定对照 A 组的合规率跨三次实验跨度 10.7pt，而 B 组跨实验差异仅 5.3pt | 小样本下单次实验的**合规率**差异不可与噪声分离（§6.8.6）；扩充用例数前，只能对**完全分离**的指标（如 #7 的 0/7 → 4/4）做断言 |
| 7 | **声明式单变量无法保证行为单变量**（§6.8.5） | 改一处 field description 会改变其他字段的生成分布；"我只改了一处"不构成其他指标未受影响的证据 |

### v2.2.0 → v2.3.0（门禁判据升维：从单测确定性比较到工业级统计容差）

#### 1. 核心架构反思与哲学对齐 (Engineering Philosophy & Reflection)
- **零容差致命缺陷复盘**：初版回归门禁实现了工程骨架，但底层判据采用了传统的严格小于判断（`curr < base`）。外部代码审计敏锐指出：在 $N=56$ 的二项分布采样下，基线 55/56 (98.2%) 的 Wilson 95% 置信区间是 `[90.6%, 99.7%]`，存在高达 7.6pt 的置信半宽。将单次峰值采样点固化为硬底线，犯了典型的「胜者诅咒（Winner's Curse）」，会导致 CI 在代码无改动时面临高达 30%+ 的随机误报率。
- **Product Engineer 研发哲学**：“在学习研究阶段抱着‘能做到最好就不糊弄’；但在实际生产中情况多变，‘边做边看’才是更符合真实市场产品的原则。” 面对高水平的外部 Code Review，我们拒绝“为了混过验收而表面修补”，必须彻底重构底层统计判据。

#### 2. 双轨门禁体系（Dual-Track Gating Architecture）

| 门禁维度 | 容差哲学 | 判据标准与工程实现 |
|---|---|---|
| **核心业务哨兵** | **严格零容差 (0%)** | `#2/#13` 维持 `logistics`，`#7` 命中 `refund`；任何一次分类漂移立即触发 `REGRESSED 🚨 (哨兵失守)` 阻断 CI。 |
| **单用例判定** | **两级阶梯容差** | 小样本（$n=4$）单次偶发失败标记为 `FLAKY_WARN ⚠️` 观察；单用例 $\ge 2$ 次失败确诊为 `REGRESSED 🚨` 阻断 CI。 |
